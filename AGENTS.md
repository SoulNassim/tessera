# AGENTS.md — Working on the Tessera repo

This file is for an AI agent changing **Tessera's own code**. If you are coding a *game* that uses Tessera, you don't need it: the note `tessera connect` wrote into your game's `AGENTS.md` says where the finished art is.

Tessera is your game's asset studio. Tessera makes the art in its own app; your coding agent copies finished files from `<game>/tessera/` using `tessera/ASSETS.md`. The Python package is still called `forge`; `tessera` is the command; `forge` and `glob` still work as aliases.

Everything lives in one public repo, `SoulNassim/tessera`: the source, the releases (installers and the update feed `forge/updater.py` reads through `brand.PUBLIC_REPO`) and the website `https://soulnassim.github.io/tessera/` (both set in `forge/brand.py`). The license is PolyForm Shield 1.0.0 (`LICENSE`): anyone may use and change Tessera, and sell the games they make with it, but not ship a competing product. Pushing a tag like `v1.0.0` runs `.github/workflows/release.yml`: it builds the Windows installer, the macOS `.dmg` and the `tessera_studio-*.whl` and publishes them as a GitHub release. A push to `main` that touches `docs/` runs `.github/workflows/pages.yml`, which publishes an allowlist of `docs/` (including `install.ps1` and `install.sh`) as the website. Users who want the app get it from the installers or the one-line installers in `docs/`.

A project inside a game is `<game>/tessera/`: `ASSETS.md`, `ASSETS.json`, `REQUESTS.md`, `README.md`, `art/` (the assets), `export/` (engine copies) and `.studio/` (everything internal). `forge/layout.py` owns every path. The old `<game>/glob/` layout (`workspace/`, `exports/`, ...) still opens; `tessera migrate` (`--dry-run`, `--undo`, `--library`) upgrades it.

## Run and test

```bash
uv run forge                          # studio + HTTP API at http://127.0.0.1:8420
uv run forge --mcp --project <name>   # MCP server over stdio
uv run --extra dev pytest -v          # tests (all pass; they never read your real ~/.forge)
```

Set `FORGE_PROJECTS_DIR` to point the MCP server and tests at another projects folder.

## The flow in one paragraph

A coding agent works on a game with placeholders. The user runs `tessera connect` once in the game folder (what [docs/agent.md](docs/agent.md) tells a new agent to run), or opens the game in Tessera. That makes the game's Tessera project in `<game>/tessera/` and writes a short note into `AGENTS.md`, `CLAUDE.md` and `GEMINI.md` about where finished art is. The user opens Tessera (its own app window; a tray icon keeps it running) and makes or picks art there, with Tessera's own chat, which runs on the user's Claude Code or Codex login. Tessera keeps `tessera/ASSETS.md`, an index of every asset: name, kind, page, the picked image or sound (`winner:`), and 3D model, rig and animation files. The coding agent reads it, copies the files it needs into the game's own folders, and keeps a placeholder for anything missing. It never edits or moves anything inside `tessera/`, and it never manages the workspace.

## Codebase map

| Path | Role |
|---|---|
| `forge/agent/connect.py` | `tessera connect` helper (also removes the old `glob` markers and skills). Writes the note about `tessera/ASSETS.md` into AGENTS.md/CLAUDE.md/GEMINI.md. |
| `forge/asset_index.py` | Writes `tessera/ASSETS.md` and `tessera/ASSETS.json`, the index the coding agent copies art from: files, icons (`tessera/export/icons/`), and placement per model (height, scale, front, points, rig points, clip loops). Reads `tessera/REQUESTS.md`, the one file the coding agent may write. |
| `forge/live_link.py` | Live Link, behind the Pipeline page (`/api/link`, `/api/link/note`): each asset's stage (concept, picked, 3D, motion, in game) and its copies in the game folder, matched by content hash against every version Tessera made (`.studio/live_link.json` keeps the hashes and version history). A copy is `current`, `stale` (an older version) or `edited` (only named like the asset). Reads the game, never writes it; `asset_index.write` adds the stale copies to `ASSETS.md` and `in_game` to `ASSETS.json`. UI: the "Pipeline" section at the end of `forge/ui/app.js` and `forge/ui/pipeline.css`. |
| `forge/local_ai/` | Settings → This PC: free images on the user's GPU. `hardware.py` reads nvidia-smi / sysctl (never imports torch) and picks the PyTorch wheel (RTX 50-series needs cu128). `catalog.py` lists the installable models with VRAM and RAM needs and picks a recommendation; only commercial-use licenses, except `personal_only` models (FLUX.1 dev), which are never recommended and need the license accepted. FLUX comes from ungated copies (city96 GGUF, OpenAI CLIP, city96 T5, diffusers VAE), never black-forest-labs (gated). `runtime.py` installs a separate venv with uv (downloading uv itself in the desktop app), downloads models from Hugging Face in a thread the page polls, removes models without breaking shared files, and moves an installed engine and models to another folder (repointing the venv). Models and their dependencies install and remove apart: `catalog.DEPS` (PyTorch, Image libraries, Cut-out add-ons) are listed under the models on This PC; installing a model with missing ones answers 409 until the page asks and resends `install_deps`, removing a model keeps them, and removing one still in use answers 409 with its users until `force`. State before this split (no `deps` key) counts as PyTorch + Image libraries installed. `engine.py` runs `worker_main.py` (stdlib + torch/diffusers only, inside that venv) over JSON lines, one job at a time, stopped after 15 idle minutes (3 for FLUX, which holds ~14 GB of RAM); `ENGINE.status()` feeds the This PC memory meter and `/api/local-ai/free` stops it at once. The worker also cuts out backgrounds with BiRefNet (`cmd: cutout`). The worker encodes SDXL prompts in 75-token pieces (no 77-token cut) and runs FLUX's T5 in its own pipeline, streaming the FLUX transformer's blocks from RAM on cards under `resident_gb`. `forge/providers/local_image.py` is the `local:<id>` image provider; an installed model counts like a key (demo mode turns off). `cutout.py` decides who removes a background: the maker's own remover (`has_own_cutout`: Meshy, GPT Image, signed-in services) when `cutout_prefer_own`, else `cutout_with` (BiRefNet when installed, or the plain flood-fill cut); `asset_studio._post_cut` runs it after makers that can't. In the UI, New art and the Generate window share one maker picker (`makerChoices`/`makerPicker` in app.js) listing this PC, keys and signed-in services together. |
| `forge/demo_rig.py` | Demo mode (no generator account, or `FORGE_DEMO_MODE=1`): every generation makes a placeholder and spends nothing. Rig and Animate use this code-built blocky biped instead of Meshy/Tripo, so Motion Studio can be tried for free; Tripo's model tools refuse. `ASSETS.md`/`ASSETS.json` mark demo files (`demo_placeholders`) so a coding agent never ships them. The tests' rig fixture is this file. |
| `forge/model_info.py` | Measures GLB / glTF models from their JSON chunk (no dependencies): size, `ground`/`top` points, rig bone points, clip lengths. Validates the viewer's `front`, `points` and `anim_loops`. The viewer (`forge/ui/viewer.js` `placementTools`) shows the 1.8 m figure, the front arrow and point markers, and picks points in the model's own coordinates. |
| `forge/game_link.py` | Link between a project and its game folder. |
| `forge/cli.py`, `forge/launcher.py` | `tessera connect` (`connect.connect_game`: make or find the game's project, write the note, open Tessera) and `tessera open`; the launcher starts Tessera in the background. |
| `forge/appwindow.py` | Opens Tessera's app window: the native window, else Edge/Chrome `--app` with its own profile (`~/.forge/browser`, no extensions), else the browser. `spawn_detached` starts processes that outlive a coding agent's job object. |

## Conventions

- Plain HTML/CSS/JS for the UI. No build step.
- Keep Tessera's writes into a game folder limited to what `connect.py` owns (the note, the `tessera/` project) and `tessera/ASSETS.md` / `tessera/ASSETS.json` (`asset_index.py`). Never write elsewhere in the game. `tessera/REQUESTS.md` belongs to the coding agent: Tessera only reads it.
- Tessera never edits the game's own folders; the coding agent does that, from `tessera/ASSETS.md`.
- Keep the advertised MCP tool list small. Legacy tools may still answer but stay unadvertised.
- Keys, tokens and `.env` never go in projects, exports or API responses.
- Add or update a test in `tests/` for every behaviour change.
- Keep `README.md`, this file and the two `tessera-assets` skill copies (`.claude/skills/` and `.agents/skills/`, identical) in sync with the code.
